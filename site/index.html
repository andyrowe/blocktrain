Verifiable agent memory — proof of what an AI did, not just a note that it did it.

As AI agents move from answering questions to taking real, irreversible actions — spending, posting, deploying — the question stops being "what does my agent remember?" and becomes "can I prove what my agent did, to someone who doesn't trust me?"

blocktrain turns an agent's action log into a record that is tamper-evident, ordered, timestamped, and portable. Each entry is hash-chained and anchored on the BSV blockchain, so any third party can later verify what happened and when — with no access to the operator's database, and even if blocktrain disappears.

Why not just a signed log file?

Because a log you control is only as trustworthy as you are. A signed file proves you stand behind it; it can't prove you didn't quietly rewrite it before signing, and it means nothing to someone who doesn't already trust you. blocktrain is for the moments where your word isn't enough:

  • an agent acting on a user's behalf, where the user wants proof of what it did with their money or account;
  • a public agent whose audience audits its posts and spends;
  • a dispute — "your agent did X" / "no it didn't" — settled by the chain, not by whoever holds the database;
  • a counterparty or regulator who needs an operator-independent trail.

If your audit is always inside your own org, you don't need this. The moment a second party has to believe you, you do.

Try it — verify this page's own proof, trusting no one

The bundle below records three real actions this agent took — an on-chain anchor, a source commit, and this site's launch — each linked to proof you can check yourself. Verify it end-to-end with a zero-dependency script (Node ≥ 18): it recomputes the hash-chain, folds each Merkle proof, reads the anchor's OP_RETURN off the public chain, and corroborates every entry's reference against WhatsOnChain, GitHub, and the open web:

curl -O https://blocktrain.org/verify.mjs
curl -O https://blocktrain.org/blocktrain-poc.json
node verify.mjs blocktrain-poc.json

It never contacts blocktrain or bsv.cx — only public BSV explorers (cross-checked, or point it at your own node with BLOCKTRAIN_EXPLORER), GitHub, and your own CPU. Output ends with ✅ VERIFIED — batch existed, in order, anchored on-chain, refs corroborated.

How it works

  1. Hash-chain — every event is canonicalized and linked to the one before (linkHashₕ = sha256(linkHashₖ₋₁ ‖ entryHashₕ)). Editing, deleting, reordering, or inserting any entry breaks the chain, detectably.
  2. On-chain anchor — the entries are sealed into an RFC 6962 Merkle batch and timestamped on BSV via bsv.cx — one transaction, any batch size.
  3. Trustless verify — anyone folds the Merkle proof to the root that is OP_RETURN-anchored on the public chain. The chain is the ground truth; no server is trusted, including ours.

Use it on your agent

Node ≥ 24 (the CLI runs TypeScript natively). Only hashes go on-chain; your log stays on your own machine — at-rest encryption is on the roadmap.

git clone https://github.com/andyrowe/blocktrain
cd blocktrain && npm install && npm link   # puts `blocktrain` on your PATH

# record what your agent did
blocktrain append --actor my-agent --kind payment --data '{"to":"acme","sats":50000}'

# corroborate an entry with an external ref anyone can check (txid / commit / url)
blocktrain append --actor my-agent --kind deploy --data '{"service":"api"}' \
  --ref git-commit:<sha>:you/repo

# commit the decision-time context too (anchored at action-time — can't be backfilled)
blocktrain append --actor my-agent --kind payment --data '{"to":"acme"}' \
  --context ./model-input.json
blocktrain context --seq 3        # show the context + prove it matches the committed hash

# seal pending entries into one on-chain batch — needs a funded mainnet key
# (pays a small bsv.cx fee): export BLOCKTRAIN_PAY_WIF=<your-wif>
blocktrain seal

# anyone can verify — trusting no one (--refs also checks the external references)
blocktrain verify --spv --refs

Or use it as an MCP server — add it to any MCP client (Claude Code, OpenClaw, …) and your agent gets the tools blocktrain_append / seal / verify / reveal / status / keygen, no per-framework glue:

{ "command": "node",
  "args": ["/path/to/blocktrain/bin/blocktrain-mcp.ts"],
  "env": { "BLOCKTRAIN_LOG": "…" } }

Prefer it automatic? Wire the PostToolUse hook and every outward action your agent takes is captured with no code changes — see the repo. Hosted (remote MCP) service on the roadmap.

Honest scope

blocktrain proves the integrity, order, and timestamp of a self-reported log. It makes tampering after the fact detectable. It does not make the agent truthful to its own log — the same limit every timestamp has. The use cases that need this (audit, dispute, debugging, accountability) don't need more.

Privacy

Shipped: the chain only ever holds a hash — never your data. Entries can also be encrypted at rest, so blocktrain (or anyone holding the log) can't read them — blind by default. Access is granted per entry to specific keys (a client, their counsel, a counterparty), so different parties see different entries; a key-holder decrypts and re-checks the content against the same on-chain hash. Built on native BSV keys — envelope encryption (AES-256-GCM payload, ECIES-wrapped per recipient).

blocktrain keygen                          # a read key: share the pub, keep the wif
blocktrain append --kind payment --data '{…}' \
  --encrypt-to <client-pub> --encrypt-to <counsel-pub>
blocktrain reveal --seq 3 --key <wif>       # authorized keys only

Scope note: the encrypted payload is private; structural metadata (kind, actor, timestamp) stays visible so the log is navigable. Coming next: a hosted blind-anchor service (P8) so clients don't run their own.

Who it's for

Agent builders, auditors, and teams whose agents act on someone else's behalf — anywhere a second party needs to trust the record without trusting the operator. Building something like that, or just curious? Open an issue or start a discussion on GitHub — we'd like to hear the use case.
