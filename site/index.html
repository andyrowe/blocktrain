blocktrain

Verifiable agent memory — proof of what an AI did, not just a note that it did it.

As AI agents move from answering questions to taking real, irreversible actions — spending, posting, deploying — the question stops being "what does my agent remember?" and becomes "can I prove what my agent did, to someone who doesn't trust me?"

blocktrain turns an agent's action log into a record that is tamper-evident, ordered, timestamped, and portable. Each entry is hash-chained and anchored on the BSV blockchain, so any third party can later verify what happened and when — with no access to the operator's database, and even if blocktrain disappears.

Try it — verify this page's own proof, trusting no one

The bundle below records blocktrain documenting its own creation. Verify it end-to-end with a zero-dependency script (Node ≥ 18). It recomputes the hash-chain, folds each Merkle proof, and reads the anchor transaction's OP_RETURN straight off the public chain:

curl -O https://blocktrain.org/verify.mjs
curl -O https://blocktrain.org/blocktrain-poc.json
node verify.mjs blocktrain-poc.json

It never contacts blocktrain or bsv.cx — only WhatsOnChain and your own CPU. Output ends with ✅ VERIFIED — batch existed, in order, anchored on-chain.

How it works

  1. Hash-chain — every event is canonicalized and linked to the one before (linkHashₕ = sha256(linkHashₖ₋₁ ‖ entryHashₕ)). Editing, deleting, reordering, or inserting any entry breaks the chain, detectably.
  2. On-chain anchor — the entries are sealed into an RFC 6962 Merkle batch and timestamped on BSV via bsv.cx — one transaction, any batch size.
  3. Trustless verify — anyone folds the Merkle proof to the root that is OP_RETURN-anchored on the public chain. The chain is the ground truth; no server is trusted, including ours.

Honest scope

blocktrain proves the integrity, order, and timestamp of a self-reported log. It makes tampering after the fact detectable. It does not make the agent truthful to its own log — the same limit every timestamp has. The use cases that need this (audit, dispute, debugging, accountability) don't need more.

Privacy

Shipped: the blockchain only ever holds a hash — never your data.

On the roadmap: off-chain contents encrypted at rest, with blind anchoring the default — blocktrain holds your proofs without being able to read them — and selective sharing with specific parties (a client, their counsel, a counterparty) without ever putting plaintext on-chain. Not built yet; described here so you know where this is going.
